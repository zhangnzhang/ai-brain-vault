# ai-brain-vault

[English](README.md) | 简体中文

一套纯 Markdown 模板，给你的 AI 助手（Claude、Codex、Cursor……）装上**共享的长期记忆和工作规矩**，而且记忆不会越用越乱。

放进 Obsidian 仓库（或任意文件夹），填几个占位符，让 AI 打开这个文件夹就能用。

## 为什么需要它

大多数"AI 记忆"方案会出三种问题：

- **失忆**：每次会话都从零开始。
- **臃肿**：什么都塞进一个大文件，每次全量加载，浪费 token，重点被淹没。
- **污染**：AI 把自己的猜测写进记忆，久而久之变成"事实"。

这套模板用几条简单约定把这三个问题一起解决。

## 包含什么

| 机制 | 怎么运作 |
|---|---|
| **分诊闸门** | AI 先判断这句话是不是工作。只有工作才加载记忆；问生活问题就正常回答，不会把工作语境扯进来。 |
| **索引式记忆** | `memory.md` 只放索引和红线（≤ 80 行），细节放在主题文件里，任务用得上才打开。 |
| **写入分级** | 低风险（项目进度、索引行）AI 直接写；高风险（事实、规则、红线、宪法）先提案，你批准才写。 |
| **会话收尾提案** | 做完实质工作后，AI 主动列出"本场值得记的"并标注去向，你点头才保存。 |
| **多个 AI 共用一个大脑** | Claude、Codex 和以后的新工具都读同一套文件，不各自存一份。 |
| **inbox 工作流** | 文章、截图丢进 `inbox/`，AI 提炼成带日期和来源的笔记，原件归档。 |
| **带日期和来源的知识** | 每篇笔记都有 `published_at` / `snapshot_at` / `content_status`，AI 能区分旧证据和当前建议。 |
| **全库地图** | `MAP.md` 告诉 AI 什么在哪、什么时候读，不预加载。 |

## 目录结构

```
.
├── AGENTS.md              # 宪法：分诊闸门、身份、记忆与知识规则
├── CLAUDE.md              # Claude 入口，指向 AGENTS.md
├── memory.md              # 索引 + 红线（每次工作会话都读）
├── MAP.md                 # 全库地图
├── memory/
│   ├── projects.md        # 一行一个项目：卡在哪、球在谁那
│   ├── projects/          # 单个项目的完整状态
│   ├── facts.md           # 长期硬事实（高风险）
│   ├── rules.md           # 工作约定与教训（高风险）
│   └── schedules.md       # 定时任务登记簿
├── knowledge/
│   ├── _index.md          # 全部笔记索引（含日期）
│   └── sop/note-template.md
├── inbox/                 # 待处理的新材料
└── logs/                  # 工作记录 + 高风险改动前的备份
```

## 快速开始

1. 点 **Use this template**（或下载 ZIP），把文件夹放到你想当仓库的位置。
2. 搜索 `{{`，替换占位符，至少替换 `AGENTS.md` 里的 `{{OWNER_NAME}}`、`{{YOUR_WORK_DOMAIN}}`、`{{NORTH_STAR_GOAL}}`。
3. 改写 `memory.md` 的红线，写成 AI 一旦做错就真会出事的那几条。
4. 让 AI 打开这个文件夹：
   - **Claude**（Claude Code / Cowork）：自动读取 `CLAUDE.md`。
   - **Codex** 等读取 `AGENTS.md` 的工具：直接可用。
   - 其他工具：建一个两行的入口文件，指向 `AGENTS.md`。
5. 开始干活。第一次实质会话结束后，批准或拒绝 AI 的记忆提案，大脑就是这样一点点长起来的。

## 使用建议

- `AGENTS.md` 和 `memory.md` 尽量短，它们每次会话都会加载；其他文件都按需读取。
- 同一条规则只写在一个文件里，其他地方用链接指向它。
- 每月让 AI 做一次体检：文件超长、断链、重复规则、过期项目、索引与实际文件不一致。
- 不要把密码、API Key、Token 放进仓库。
